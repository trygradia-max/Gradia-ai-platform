## Queue

### 1. C4a — job status machine + job card
Per spec §C4. Status flow on `appointments`: booked → confirmed → checked_in → in_progress → on_hold(reason) → completed → paid → closed. Every transition = one tap from the job card, writes the customer timeline. `checked_in` prompts walk-around photos; `completed` prompts after-photos, arms the review-request hook (delivery lands in C5 item 3), and sets `maintenance_schedule.next_due_at` on the vehicle from service-category intervals (defaults in code, owner-editable later). `closed` auto-sets 48h after paid (sweep function, exported). Mobile fields render only when `location_type='mobile'` (address/maps link, travel fee, water/power/gate/parking, weather flag); shop fields otherwise (bay, drop-off/pickup, key tag). Tests: every transition reachable + timeline write + completed side-effects.

### 2. C4b — Calendar page (5th nav destination)
Per spec §C4 and the approved IA. Desktop: week grid, jobs as status-colored blocks, bay lanes when shop jobs have bays, drag-to-reschedule (updates the job; any customer-facing notification stages an approval), block-time support, capacity warning when a day exceeds the booking-rules working hours. Mobile: the day list in drive order (mobile jobs sorted into a sane visiting order by scheduled time; true optimization is out of scope) — one-tap status, photo capture, maps link. This screen is the solo mobile detailer's whole day: acceptance is "run a full day phone-only." Old schedule URLs (if any) redirect per the layer-2-shell pattern.

### 3. C5 — automation catalog (toggles, not a builder)
Per spec §C5, tables from C1 (`automations`, `automation_runs`). Settings page: the 8 catalog entries as plain-English sentences with toggle + mode (approval|autopilot) + editable message template + run history ("recovered N bookings"). Wiring, in code, from real events:
- #1 new_lead_instant (5-min no-contact) and #2 missed_call_textback — default autopilot
- #3 quote_followup — wire the existing exported `advanceQuoteFollowUps` sweep through the catalog (2d/5d/12d, escalating copy) — default approval
- #4 lead_revival (21d silent) — approval
- #5 appt_confirmation and #6 appt_reminder — **refactor the existing confirm/reminder machinery into catalog entries with ZERO behavior change for existing shops** (tests prove it)
- #7 job_completed (thanks + photos + cure/care copy per services performed) — autopilot
- #8 review_request (4h after completed, tunable; uses the existing review-link settings) — approval
Hard floor: catalog entries touching money or calendar can never be autopilot — enforce in `isAutonomyAllowed()`, add the locking test. Approval mode stages `pending_actions` (queue visible in /approvals); autopilot sends via safe_send and logs to timeline + automation_runs. Sweeps ride existing hourly crons where possible (see rail).
